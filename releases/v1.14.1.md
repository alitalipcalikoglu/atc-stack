# atc-web production suite 1.14.1

Release date: 2026-10-14

This immutable patch release supersedes `v1.14.0` as the supported default installation. It
completes the `atc-` rename where `v1.14.0` left old names behind, and fixes defects found while
verifying the renamed suite end to end.

## Version identities

- All 15 repositories: `v1.14.1`.
- Historical tags, including `v1.14.0`, remain immutable.

The authoritative installer descriptor is
[`../installation-manifests/v1.14.1.json`](../installation-manifests/v1.14.1.json).

## Contract fixes

- Every `/v1/info` schema now declares the real service id (`const: atc-notify`, ...); `v1.14.0`
  specs still declared the old id. Notify's `service` and `apiVersion` also declare
  `type: string`.
- Console: the service `type` enum, the documentation service id enum and the operation tags use
  the `atc-` names.

## Console fixes

- Service icons on the overview, the sidebar and the mobile navigation were replaced by the
  fallback icon after the rename; the icon map is keyed by the new types again.
- Opening the console after a redeploy, while the browser still ran the previous service worker,
  threw `effect_update_depth_exceeded` and left pages without content. The update-toast effect now
  depends only on the update state.
- Ranked lists clip long labels and subtitles inside their row, and audit action names no longer
  wrap at the hyphen.
- The `scripts/overflow-probe.js` layout probe used for visual checks is part of the repository
  again.

## Stack fixes

- `stack setup`, `stack dev`, `stack status` and the `--matrix` table size the service column from
  the longest id, so `atc-webhook-out` is no longer cut off; the matrix status column has a gap.

## Documentation

- Paths, commands, links, PM2 app names, Docker container and volume names, query examples,
  key holder ids, `services.example.json` and route manifests use the `atc-` names everywhere.
- The `v1.14.0` notes no longer describe a migration for installations that never existed.

## Pre-publication validation

- Every repository passed its full suite after `npm ci`: Gateway 52, Notify 60, Auth 44, Media 79,
  Audit 46, Shortlink 23, Flags 20, Scheduler 47, Webhook-out 45, Search 14, Ratelimit 33, Geo 44,
  Console 131, and `atc-service-core` 98. Every typecheck was clean and every production audit
  reported zero vulnerabilities.
- Stack passed 92/92 with integration enabled and zero skips. All 13 specs validated at 376
  operations; `/v1/info` parity was clean; generated clients showed no drift with 6/6 tests and
  3/3 real pilots; MCP remained 10 tools with 17/17 unit and 14/14 protocol E2E tests.
- Console build, runtime, auth, M4, M5, M6, M7 and real-Chrome browser smokes passed. A visual
  check of 18 pages at 1280 and 375 px with the overflow probe reported no overflow and no page
  errors, including the redeploy-with-old-service-worker case.
- `stack setup` then `stack dev` in the workspace reached 13/13 ready; a second `setup` left every
  `.env` byte-identical; foreground shutdown exited every service cleanly.
- All 13 Docker images built, ran as the non-root `node` user, reported `healthy` with their
  `atc-` identity, and stopped on SIGTERM with exit code 0.

Exact tag identities and post-publication default-install evidence are recorded in `v1.14.1.json`.
No GitHub Release object or GitHub Actions workflow is part of this release policy.
