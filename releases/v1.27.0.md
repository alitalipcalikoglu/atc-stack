# atc-web production suite 1.27.0

Release date: 2026-10-16

All 22 repositories at `v1.27.0`: 20 HTTP services, `atc-service-core` and `atc-stack`. The installer
descriptor is [`../installation-manifests/v1.27.0.json`](../installation-manifests/v1.27.0.json),
selected by [`../installation-manifests/supported.json`](../installation-manifests/supported.json).

## Identity (atc-auth)

- End-user MFA: TOTP (each code accepted once) and ten one-time recovery codes. Secrets are encrypted
  with `MFA_SECRETS_KEY`; without it the MFA routes answer `503`.
- A correct password on an MFA account answers `401` with code `MFA_REQUIRED` and an `mfaToken`;
  `POST /v1/auth/login/mfa` completes the sign-in. The token allows five tries and wrong codes count
  toward the normal lockout.
- Routes: `mfa/setup`, `mfa/enable`, `mfa/disable` (password and code), `mfa/recovery-codes`, and
  the admin route `DELETE /v1/users/:id/mfa`.
- Password history (`PASSWORD_HISTORY`, default 5, current password included).
- Optional breached-password check against the HIBP range API, off by default; a network failure
  lets the password through.

## Console

- Users show an MFA badge and a "Reset MFA" action behind the confirm dialog.
- App-bar buttons no longer shrink below their content; on phones, toasts move to the top while a
  dialog is open.

## Stack

- Setup generates `MFA_SECRETS_KEY`. MFA routes are excluded from the MCP tools.

## Breaking changes

- auth migration v4. Callers must check `error.code` before treating a sign-in `401` as a wrong
  password.

## Not verified against a live system

The HIBP check ran only against a mocked response in the documented format.
