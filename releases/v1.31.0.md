## High availability

One active host plus a warm standby; there are never two writers on one database.

- **atc-gateway:** active health checks of every upstream (`UPSTREAM_HEALTH_INTERVAL_MS`, default
  5 s, `0` turns them off). A failing upstream leaves rotation before a client request reaches it
  and rejoins within one interval after it recovers.
- **atc-backup:** `npm run standby -- <source> <target-file>` pulls the primary's newest backup on the
  standby host, checks its SHA-256, decrypts it, runs an SQLite integrity check and swaps the file
  in. Folder backups are unpacked by hand.
- The stack README has a "High availability" section with a failover runbook. Data loss on
  failover is at most the backup interval plus the pull time.

## Console

- Audit cross links: item pages open their audit events, and audit events link back to the item.
