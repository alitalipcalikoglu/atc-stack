# atc-web production suite 1.14.0

Release date: 2026-10-14

This immutable release supersedes `v1.13.0` as the supported default installation. It renames
every repository and every service identity with an `atc-` prefix. This is a breaking change for
existing installations and for external API clients; read "Upgrading" before you move to it.

## Version identities

- All 15 repositories: `v1.14.0`.
- Historical suite tags `v1.0.0` to `v1.13.0` and `service-core` tags `v1.11.1` to `v1.13.0` remain
  immutable. They keep the old repository names inside their manifests; GitHub redirects the old
  repository URLs, so they stay installable with the Stack checkout of their own tag.

The authoritative installer descriptor is
[`../installation-manifests/v1.14.0.json`](../installation-manifests/v1.14.0.json).

## What was renamed

- GitHub repositories and workspace folders: `notify` is now `atc-notify`, and so on for all 15
  (`atc-service-core`, `atc-stack`, `atc-console`, ...).
- npm package names: `@atc-web/atc-<name>`. Services import `@atc-web/atc-service-core/...`.
- Service ids everywhere: PM2 process names, Stack manifest ids, Console service ids and types,
  the `service` field of `/v1/info`, OpenAPI `info.title`, and API key holder ids (so the audit
  `source` of an event is now `atc-auth`, `atc-console`, ...).
- OpenAPI `operationId` prefixes for all 376 operations: `notify.messages.create` is now
  `atc-notify.messages.create`. Webhook-out's former `webhookOut.` and `webhook.` prefixes are
  unified as `atc-webhook-out.`.
- Audit action names: `atc-notify.message.create`, `atc-auth.login.succeeded`,
  `atc-console.atc-auth.user.create`, ...
- MCP tool names: `atc-stack.status`, `atc-notify.messages.list`, ... and the generated client
  folders `clients/typescript/atc-<name>/`.
- Console URLs: service pages move to `/atc-<type>/<sid>/...` and service APIs to
  `/api/services/<sid>/atc-<type>/...`. The local Console activity log stays at `/audit`.
- Scheduler `TARGET_KEYS` names written by Stack: `atc-flags`, `atc-notify`, `atc-webhook-out`.

## What was deliberately not renamed

- Environment variable names (`NOTIFY_URL`, `NOTIFY_API_KEYS`, `STACK_MCP_NOTIFY_BASE_URL`, ...).
- Database file names (`notify.db`, ...), error codes, and Prometheus metric names and labels.
- Gateway public route prefixes (`/api/auth/`, `/api/media/`, `/files/`) and gateway route ids.
- Console UI preferences in browser storage (`console.theme`, `console.lang`).

## Other changes

- Audit accepts a hyphen in the first segment of `action` and `actionPrefix`
  (`^[a-z0-9][a-z0-9-]*(\.[a-z0-9_-]+){1,5}$`). Existing action names stay valid.
- Media: `sharp` `0.35.5` for CVE-2026-96889 (high, librsvg).
- Stack MCP: `@modelcontextprotocol/sdk` `1.32.1` for GHSA-6qxp-vccf-f47h (high, OAuth client; not
  reachable from the STDIO server, upgraded to keep the audit at zero).

## Upgrading an existing installation

1. Stop the old processes: `pm2 delete notify auth media ...` (the old PM2 names).
2. Rename each service folder to `atc-<name>` and update its git remote to the new repository.
3. Run `stack setup` from `atc-stack`. It writes new API key holder ids next to the old ones and
   regenerates Console `services.json` and gateway `routes.json`. Old key entries stay in `.env` as
   unused lines until you remove them.
4. Update scheduler jobs that reference a target key by its old name (`flags`, `notify`,
   `webhook-out`).
5. Update external callers that match on operationIds, audit action names, audit `source` values,
   Console URLs or MCP tool names.

Audit history keeps its old `source` and `action` values; new events use the new names, so queries
across the upgrade need both.
