# atc-web production suite 1.19.0

Release date: 2026-10-14

All 22 repositories at `v1.19.0`: 20 HTTP services, `atc-service-core` and `atc-stack`. The installer
descriptor is [`../installation-manifests/v1.19.0.json`](../installation-manifests/v1.19.0.json),
selected by [`../installation-manifests/supported.json`](../installation-manifests/supported.json).

## New services

- **atc-queue** (port 3016): durable job and message queues for service-to-service work. Named
  queues, enqueue with delay, priority and dedupe keys, leased delivery with ack, nack and extend,
  retries with backoff, dead-letter queues with redrive, purge and per-queue stats. Keys can be
  scoped to a set of queues.
- **atc-backup** (port 3017): scheduled online SQLite backups of every service database through the
  `node:sqlite` backup API, followed by an integrity check and a SHA-256 checksum. Retention,
  download, verify, restore into a separate directory, and live restore only when
  `ALLOW_LIVE_RESTORE` is set, the request carries a typed confirmation and a safety backup succeeds.
  Backup files are owner-only (directories 0700, files 0600); copies can go to atc-media.
- **atc-status** (port 3018): uptime monitors for URLs with interval, timeout and expected status,
  an SSRF guard for monitors created through the API, incidents that open after repeated failures
  and close on recovery, e-mail alerts through atc-notify, and a public status page and JSON summary
  served through the gateway. The stack seeds `/health` and `/ready` monitors for every service.
- **atc-payments** (port 3019): payment intents, cancels and refunds through the Stripe REST
  API, required idempotency keys, webhooks verified in constant time, a payment state machine, an
  append-only ledger, and events to atc-webhook-out and audit. Without `STRIPE_SECRET_KEY` the
  provider is disabled and `/ready` says so.

Each ships with keys and roles, audit events, metrics, an `/v1/info` contract, a Dockerfile, a PM2
ecosystem file, examples, and Console pages with an overview card.

## Other changes

- **Console:** content, export and render requests carry the signed-in admin as `X-Actor`; those
  services trust it only from keys listed in `ACTOR_KEYS` and record the admin as creator and audit
  actor. Content imports and render previews accept bodies up to 2 MiB; every other route keeps
  64 KiB.
- **atc-media** accepts `application/vnd.sqlite3` when it is listed in `ALLOWED_TYPES`.
- **Stack:** `npm run compose` writes a Docker Compose setup for the whole suite (owner-only env
  files, optional `--port-offset`), and `npm run load` runs a fetch-based load test against the
  gateway and reports latency percentiles, errors and rate-limited responses.
