# atc-web production suite 1.25.0

Release date: 2026-10-15

All 22 repositories at `v1.25.0`: 20 HTTP services, `atc-service-core` and `atc-stack`. The installer
descriptor is [`../installation-manifests/v1.25.0.json`](../installation-manifests/v1.25.0.json),
selected by [`../installation-manifests/supported.json`](../installation-manifests/supported.json).

This release follows a full review of every service against its purpose. It breaks compatibility on
purpose: nothing was deployed yet, so several migrations were rewritten and local databases of
`atc-status`, `atc-backup` and `atc-payments` must be recreated.

## Correctness and durability

- **atc-payments:** refund reconciliation (`sync`) lists refunds from Stripe in the documented
  response shape; payment audit events go through a durable outbox; PII anonymization and
  reconciliation endpoints; disputes are recorded as `payment.disputed` events.
- **Audit:** every service exposes audit delivery counters; the audit chain anchor is enabled by the
  stack.
- **atc-queue:** long-poll no longer takes the write lock for every idle consumer.
- **atc-shortlink:** disabled or expired links are no longer cached for 24 hours; clicks are
  aggregated and flushed in batches, with raw rows pruned after `CLICK_RAW_DAYS`.
- **atc-media:** per-key upload limit (`KEY_MAX_UPLOAD_BYTES`), quotas (`KEY_QUOTA_BYTES`,
  `DEFAULT_QUOTA_BYTES`, `MIN_FREE_BYTES`) and `GET /v1/usage`.
- **atc-backup:** encrypted backups (`BACKUP_ENCRYPTION_KEY`, owned by the operator), configurable
  trees (`BACKUP_TREES`), and restore drills (`POST /v1/backups/:id/drill`, `DRILL_INTERVAL_HOURS`).

## Events and alerts

- Services publish events through `atc-webhook-out` into an alert hub in `atc-status`
  (`EventPublisher`, nine publishers). Backup failures, dead letters, closed subscriptions and
  scheduler failures now reach people.
- `atc-status` adds keyword, TCP, TLS-expiry and heartbeat monitors (`/v1/ping/:id/:token`);
  `atc-scheduler` can target more services; `atc-export` reads more sources.
- Console: alerts page, search document upload, admin-only export and backup downloads.

## Security and identity

- **atc-auth:** email change, per-address lockout with backoff, session cap (`MAX_SESSIONS`),
  new-device notice (`NEW_DEVICE_EMAIL`), personal data export and anonymization. All password
  checks (sign-in, email change, password change) share one verification with lockout.
- **atc-console:** per-admin service scope, enforced TOTP (`CONSOLE_REQUIRE_TOTP`), password checks
  with lockout.
- **atc-notify:** keys carry a role (`id:secret[:read|readwrite|admin]`); an admin key sees every
  key's messages. **atc-content:** keys can be scoped to namespaces; the gateway key is limited to
  `public`.
- **atc-service-core:** API keys can expire (`@YYYY-MM-DD`), record last use and expose key
  metrics. Every service depends on this core tag, so these take effect.

## Performance and operations

- Render runs PDF generation in worker threads (`RENDER_WORKERS`); geo reloads MMDB files safely
  and reports their age (`MMDB_MAX_AGE_DAYS`); flags count evaluations; search accepts documents
  from the console.
- Stack: `npm run load -- --profile writes`, Prometheus alert rules in `docs/prometheus/alerts.yml`,
  `npm run deps:check`, `npm run sbom`, scaling-model and backup-mount documentation, new
  integration tests across services, and `smoke:browser` runs the overflow probe at both widths.
- `npm run mcp:config` writes read-only keys on a first setup; use `--full` for write tools.

## Breaking changes

- `atc-status` and `atc-backup` migration 1 were rewritten; recreate `status.db` and `backup.db`.
  The same applies to `atc-payments` data. Console migration v4, auth v3, shortlink v2 and flags
  migration 1 changed too.
- notify and content key formats gained fields (see above).
- New environment variables: `KEY_MAX_UPLOAD_BYTES`, `KEY_QUOTA_BYTES`, `DEFAULT_QUOTA_BYTES`,
  `MIN_FREE_BYTES`, `RENDER_WORKERS`, `CLICK_FLUSH_MS`, `CLICK_RAW_DAYS`, `MMDB_MAX_AGE_DAYS`,
  `WEBHOOK_OUT_*`, `BACKUP_TREES`, `BACKUP_ENCRYPTION_KEY`, `DRILL_INTERVAL_HOURS`,
  `HEARTBEAT_URL`, `AUDIT_SAMPLE_SEC`, `LOGIN_MAX_FAILURES_TOTAL`, `MAX_SESSIONS`,
  `NEW_DEVICE_EMAIL`, `CONSOLE_REQUIRE_TOTP`.

## Not verified against a live system

Stripe was exercised only against fixtures that mirror its documented responses; the opt-in
`test/live-stripe.test.js` runs with `STRIPE_TEST_SECRET_KEY`.
