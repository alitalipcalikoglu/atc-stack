# atc-web production suite 1.30.0

Release date: 2026-10-16

All 22 repositories at `v1.30.0`: 20 HTTP services, `atc-service-core` and `atc-stack`. The installer
descriptor is [`../installation-manifests/v1.30.0.json`](../installation-manifests/v1.30.0.json),
selected by [`../installation-manifests/supported.json`](../installation-manifests/supported.json).

This release makes the API conventions the same in every service. It breaks compatibility on
purpose; see the stack README "Conventions" section.

## Pagination

- Every list returns `{ items, nextCursor }`; a complete list returns `nextCursor: null`.
- Paging is `limit` plus an opaque `cursor`. `before`, `offset`, `beforeSeq` and `nextBefore` are
  removed. Search results use `items` instead of `hits`.

## Idempotency

- `Idempotency-Key` is opt-in per route and implemented once in `atc-service-core`
  (`./idempotency`). Stored answers are scoped to the API key, `X-Actor` and the access-token
  subject.
- Routes that return a secret (MFA setup, ping tokens, webhook secrets, media tickets and signed
  URLs) never store answers.
- atc-payments keeps its required key; a stored payment now also belongs to the caller behind the
  key, and another caller gets `409 IDEMPOTENCY_MISMATCH`.

## Identifiers

- One id format from `atc-service-core` (`./ids`): new prefixes `exp_`, `rnd_`, `mnt_`, `sub_`,
  `adm_` and `ses_`; audit events use `aud_`. Log rows expose `seq`.
- Console schema v5 maps existing admins to `adm_` ids and ends every open session once.

## Breaking changes

- List response shapes and paging parameters in every service.
- Id formats in auth, media, notify, webhook-out, flags, export, render, status, audit and console.
  Local data of those services was recreated.

## Validation

Recorded in [`v1.30.0.json`](v1.30.0.json) by `release:verify` and `release:publish`.
