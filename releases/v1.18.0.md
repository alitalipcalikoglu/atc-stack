# atc-web production suite 1.18.0

Release date: 2026-10-14

All 18 repositories at `v1.18.0`: 16 HTTP services, `atc-service-core` and `atc-stack`. The installer
descriptor is [`../installation-manifests/v1.18.0.json`](../installation-manifests/v1.18.0.json),
selected by [`../installation-manifests/supported.json`](../installation-manifests/supported.json).

## New services

- **atc-content** (port 3013): translations and content strings. Namespaces with locales and
  fallback chains, keys with `{name}` placeholders checked against the default locale, draft edits,
  immutable numbered releases with rollback, JSON import/export, and published bundles at
  `GET /v1/bundles/:ns/:locale` with strong ETags. The gateway serves bundles publicly at
  `/api/content/v1/bundles/*` with a read-only key.
- **atc-export** (port 3014): background exports to CSV or NDJSON from audit, auth, shortlink,
  flags, media and content. A durable worker (lease, heartbeat, crash recovery, retries) streams the
  output into a private atc-media file, guards CSV cells against formula injection, emails through
  atc-notify when asked, and deletes jobs and files after a retention period.
- **atc-render** (port 3015): PDF documents from versioned JSON layout templates (headings, text,
  key/value lists, tables that repeat their header across pages, images from atc-media, QR codes,
  conditional blocks, headers and footers with page numbers). Built on `pdfkit` with the DejaVu
  fonts vendored in the repository, so Turkish and other Latin text renders correctly.

Each ships with keys and roles, audit events, metrics, an `/v1/info` contract, a Dockerfile, a PM2
ecosystem file, examples, and Console pages with an overview card.

## Other changes

- **atc-gateway** rejects request paths that contain `.` or `..` segments or an encoded dot, slash
  or backslash with `400 INVALID_PATH`, before route matching.
- **atc-media** accepts `text/csv` and `application/x-ndjson` when they are listed in
  `ALLOWED_TYPES`, the name has the matching extension and the bytes are valid UTF-8.
- **Console:** export downloads and render previews stream through the console as attachments with a
  sandbox CSP, so the browser never needs to reach media directly. Render sample data is kept in
  memory for the signed-in session only, never in browser storage.
- **Stack:** the release manifest is built from the repository catalog, so new repositories enter
  the next release; `install:all --ref main` no longer needs a released descriptor entry.
