# atc-web production suite 1.16.0

Release date: 2026-10-14

All 15 repositories at `v1.16.0`. The installer descriptor is
[`../installation-manifests/v1.16.0.json`](../installation-manifests/v1.16.0.json), selected by
[`../installation-manifests/supported.json`](../installation-manifests/supported.json).

## Changes

- **Console media byte ranges:** the file-bytes relay forwards one `bytes=` range to media, so
  video and audio previews can seek. Media's `206` (with `Content-Range`) and `416` pass back;
  multi-range and other units are not forwarded and the whole body is served. The OpenAPI operation
  and the generated client describe the `Range` header and both responses.
- **Console cache lifetimes:** the API response hook no longer overrides a route's own
  `Cache-Control`. Media bytes keep `private, max-age=300` and QR images `private, max-age=3600`;
  every other API response stays `no-store`.
- **Swagger transfer bound:** the lazy `/docs` renderer downloads as about 327 KB brotli and is
  cached as immutable; the M7 build smoke fails above 400 KB.
- **Release tooling:** `stack release:prepare`, `release:verify` and `release:publish` run the
  whole local release flow, resumably (README, "Releasing"). This release is the first one made
  with them.
- **Documentation checks:** stack fails its tests when a document names an older suite version, and
  `atc-service-core` checks that its install examples pin the current tag. Console examples use the
  `atc-` service paths.
