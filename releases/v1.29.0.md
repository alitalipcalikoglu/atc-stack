# atc-web production suite 1.29.0

Release date: 2026-10-16

All 22 repositories at `v1.29.0`: 20 HTTP services, `atc-service-core` and `atc-stack`. The installer
descriptor is [`../installation-manifests/v1.29.0.json`](../installation-manifests/v1.29.0.json),
selected by [`../installation-manifests/supported.json`](../installation-manifests/supported.json).

## Console

- Every service page has an API docs action that opens the docs for that service.
- Help tips ("?") on page titles, form titles and every form field, in English and Turkish.
- New pages and dialogs for the service additions below.

## Services

- **atc-status:** DNS monitors; maintenance windows, incident updates and subscribers.
- **atc-flags:** two-person approval for production changes. A copy request stores the source state
  at request time; approval refuses with `409 CHANGE_STALE` if either environment changed since.
- **atc-media:** optional ClamAV scan (`CLAMD_HOST`) with quarantine; admin keys and file owners.
- **atc-shortlink:** batch creation; optional Safe Browsing check.
- **atc-render:** asynchronous render jobs; custom fonts from `FONTS_DIR`.
- **atc-ratelimit:** in-memory backend.
- **atc-geo:** national numbering plans.
- **atc-queue:** push delivery. `PUSH_ALLOW_PRIVATE` requires `PUSH_ALLOWED_HOSTS`; the resolved
  address is checked on every delivery, and link-local and cloud metadata addresses are always
  refused.
- **atc-content:** ICU message formatting and a review step.
- **atc-export:** resumable exports and size caps.
- **atc-payments:** dispute records and workflow.

## Breaking changes

- `atc-status` migration 1 was rewritten; recreate `status.db`.
- The stack no longer allows queue push to HTTP or private addresses.

## Not verified against a live system

Stripe disputes, Safe Browsing and ClamAV were exercised only against fakes; the stack leaves Safe
Browsing and ClamAV off.
